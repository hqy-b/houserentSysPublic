## 2. P0：空 id 整表软删

`docs/31` 登记的 P0：`sys_dict`、`sys_menu`、`sys_message` 的 `delete` 使用 `where 1=1` + `<if id>`，当 id 为空时 SQL 退化为整表软删。

修复：三个 mapper 的 `delete` 改为强制主键条件：

```sql
update sys_dict set del_flag = 1 where id = #{id}
```

| 文件 | 变更 |
|---|---|
| `mapper/common/DictDao.xml` | `where 1=1 + <if>` → `where id = #{id}` |
| `mapper/common/MenuDao.xml` | 同上 |
| `mapper/common/MessageDao.xml` | 同上 |

修复后空 id 只会命中 `id = NULL/'',` 0 行，不再有整表软删路径；非空 id 行为与原来一致。

## 3. P1：详情查询空结果 NPE

原实现直接对 `super.get(id)` 的结果取属性；id 不存在或为空时抛 NPE。

| 文件 | 修复 |
|---|---|
| `HouseResourceService.get` | id 为空直接返回 null；查不到返回 null，不拼图片/标签 |
| `ApplyRentService.get` | 查不到返回 null，不再 `applyRent.getHouseId()` |
| `ApplyViewService.get` | 查不到返回 null，不再 `applyView.getHouseId()` |

列表/分页里即使房源查不到，也只会把 `houseResource` 置 null，不再中断整个分页。

## 4. Logback 轮转（JSON）

新增 `src/main/resources/logback-spring.xml`：

- 控制台保留原文本格式，便于本地看；
- 文件日志 `logs/hrent-json.log` 单行 JSON；
- `SizeAndTimeBasedRollingPolicy`：按天 + 单文件 50MB，保留 14 天，总上限 2GB，历史文件 gzip；
- 字段：`timestamp / level / logger / thread / message / traceId / mdc / exception`；
- `V2TraceFilter` 把 traceId 放入 MDC，v2 请求日志可被 Loki/Filebeat 直接按字段检索。

自定义 `JsonLogLayout` 使用项目已有 Jackson，未新增日志编码器依赖。实测输出：

```json
{"timestamp":"2026-11-16T13:58:44.446Z","level":"INFO","logger":"com.zaxxer.hikari.HikariDataSource","thread":"SpringApplicationShutdownHook","message":"hrent-pool - Shutdown initiated..."}
```

证据：`hrent-api/logs/hrent-json.log`（8.6 KB，单测上下文生成）。
